# Инфузия: база данных и формат персонажа

Данные вынесены из Google Sheets в обычные JSON-файлы. Всё лежит в репозитории, правится прямо на GitHub и читается любой страницей на GitHub Pages через `fetch`.

```
items/       items.json, items.schema.json     каталог предметов (622)
cards/       cards.json, cards.schema.json     каталог карт (274)
rules/       ranks, stats, skills, abilities, beasts, traits, essences,
             classes, slots, implant-combos, formulas   справочник правил (бывший «Альманах», лист БНЗОМ и СаппортСводка)
character/   character.schema.json             формат сохранения персонажа
             example-takane-aki.json           живой пример
             calc.js                           расчёты (ОЗ, Кронос, очки, щепки, слоты, цена продажи)
tools/       validate.mjs                      проверка базы и персонажей
```

## Идентификаторы
У каждого предмета, карты, навыка и способности есть постоянный `id` (например `acs-para-naruchnikov-c`). Название и описание можно менять свободно, `id` не менять: на него ссылаются сохранённые персонажи. Новая запись получает новый уникальный `id` (латиница, цифры, дефисы; в конце буква редкости c/u/r/e/l/k).

## Персонаж
Один файл `.json`. Предметы, навыки, способности, черта и ранг хранятся ссылками на `id`, текст описаний в файл персонажа не копируется. Из персонажа в файл попадают только его собственные данные: характеристики, уровни навыков, количество предметов, заметки.

## Расчёты и ручные значения
`calc.js` считает по формулам из прежних таблиц:

| Значение | Формула |
|---|---|
| Свободные очки | 56 − сумма характеристик |
| Макс. ОЗ | база ранга + Телосложение × 25 |
| Макс. Кронос | по рангу (таблица в `rules/ranks.json`) |
| Щепки за навык | (ступень навыка − 4) × уровень |
| Навык доступен | характеристика ≥ ступень навыка |
| Цена продажи | 5% от стоимости, округление как в таблице |
| Слоты | лимит по тегу, статус: Свободно / ОК / Занято / Сверх Лимита! |

Любое из этих значений можно задать вручную в `overrides` персонажа (`null` = считать по формуле). Ответ `derive()` всегда содержит `{ value, auto, overridden }`, так что интерфейс может показать и своё значение, и расчётное.

## Проверка
```
node tools/validate.mjs                      # проверяет каталоги и пример
node tools/validate.mjs путь/к/персонажу.json
```
Проверяются уникальность `id`, существование всех ссылок и класс персонажа. Скрипт можно запускать в GitHub Actions.

## Известные допущения
- ИЧ (ёмкость имплантов) хранится как есть (`implantCapacity`) и не пересчитывается: по таблицам не видно, сколько ИЧ занимает обычный имплант. Особый случай «Психологический карантин» описан в `rules/implant-combos.json`.
- Автомастерская (Кочевник) в базу не входит.
- Ручных цен продажи в каталоге не оказалось: все 622 значения совпали с 5% от стоимости.
