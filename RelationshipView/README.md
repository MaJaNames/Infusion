# Карта связей

Отдельный экран для заметок о персонажах, организациях и их отношениях: граф как
в Obsidian, но данные — обычный JSON.

Прямая ссылка после публикации:
<https://majanames.github.io/Infusion/RelationshipView/>

## Что умеет

- Силовая раскладка графа: перетаскивание узлов, панорамирование,
  масштаб колесом, щипком и кнопками, «Вписать» по клавише `F`.
  Перетаскивание не закрепляет персонажа: раскладка остаётся живой. Закрепить
  или открепить можно кнопкой в карточке; «Раскладка» закрепления не снимает.
- Клик по персонажу открывает карточку: имя, категория, теги, отметка
  «Недоступен» (точное состояние — мёртв, пропал, арестован — пишется в заметке),
  заметка и список связей. Клик по связи — подпись, тип, направление и заметка.
- Между одной парой можно провести **несколько стрелок** (в том числе встречных):
  повторное «Связать» добавляет новую связь, а не открывает старую. Параллельные
  рёбра рисуются дугами, поэтому обе подписи видны. В карточке связи есть кнопка
  «Поменять направление». Стрелки увеличены: толще линия и крупнее наконечник.
- **Организации — обычные ноды** категории `org` («первичные центры»). Кнопка
  «＋ Организация» (`Z`) создаёт такую ноду; с ней можно делать связи так же,
  как с человеком. Отношение к организации и отношение к человеку внутри неё —
  разные стрелки.
- **Фракция задаётся полем `faction` у ноды.** В карточке это выпадающий
  список уже существующих фракций и пункт «＋ Новая фракция…»; у ноды-организации
  фракция совпадает с названием и переименовывается вместе с ним. В обзоре есть
  список фракций с числом нод: клик вписывает все ноды фракции в экран.
- **Блибы чисто визуальные.** Ноды одной фракции сливаются в общий блиб, только
  если стоят достаточно близко; иначе фракция даёт несколько локальных блибов,
  и огромная оболочка не накрывает полкарты. Ноды без фракции остаются
  свободными и серой окантовки не получают. Оболочка строится по окружностям нод
  и прямоугольникам их подписей, поэтому ни кружки, ни текст не выходят за край.
  Блибы не задают позиции и ни на что не влияют: положение и фракции определяют
  их, а не наоборот. Если в блибе есть организация с тем же названием, отдельный
  заголовок блиба не рисуется — подписи ноды достаточно.
- **Раскладка — только связи и близость, как в Obsidian.** Пружины действуют
  по рёбрам, плюс короткое отталкивание не даёт нодам слипаться. Фракции и блибы
  на физику не влияют вообще. Перетаскивание замораживает раскладку: двигается
  только взятая нода, остальные остаются на местах.
- `[[Имя]]` в заметке рисует пунктирную связь с персонажем или организацией (если
  они есть на карте). В предпросмотре заметки такие ссылки кликабельны.
- Поиск по имени, тегам и заметкам, фильтр по категориям, подписи связей.
- Автосохранение в `localStorage` (`infusion.relationships`).
- JSON: скачать/загрузить копию, привязать файл через File System Access API
  (Chromium). Изменения дописываются в привязанный файл автоматически,
  `Ctrl+S` сохраняет сразу и запрашивает разрешение, если оно истекло. Если
  браузер не умеет привязку, остаются скачивание и загрузка JSON.

«Загрузить пример» строит карту без личных имён: роли («Напарник», «Медик»,
«Заказчик»…), шесть нод-организаций по фракциям игры (ЧР, ГРА, Ацуши,
Икс-Экшен, Гончие, Хиллз), встречные стрелки, связи с организацией и с людьми
внутри неё. Позиции в примере подобраны вручную и не закреплены: при
перетаскивании остальные ноды не двигаются, потому что раскладка на это время
замирает.

## Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| `N` | добавить персонажа |
| `Z` | добавить организацию (ноду-центр) |
| `F` | вписать граф в экран |
| `/` | фокус на поиске |
| `Delete` | удалить выбранную ноду или связь |
| `Esc` | отменить режим связи / снять выделение |
| `Ctrl+S` | сохранить в привязанный JSON-файл (или скачать копию) |

## Формат JSON

```json
{
  "v": 1,
  "updatedAt": 1763500000000,
  "nodes": [
    {
      "id": "org_chr",
      "label": "ЧР",
      "group": "org",
      "faction": "ЧР",
      "tags": [],
      "dead": false,
      "x": -330,
      "y": 100,
      "fixed": true,
      "notes": "Первичный центр организации."
    },
    {
      "id": "me",
      "label": "Мой персонаж",
      "group": "self",
      "faction": "",
      "tags": [],
      "dead": false,
      "x": 0,
      "y": 0,
      "fixed": true,
      "notes": "Старается не злить [[ЧР]]."
    },
    {
      "id": "medic",
      "label": "Медик",
      "group": "acquaintance",
      "faction": "ЧР",
      "tags": [],
      "dead": false,
      "x": -260,
      "y": 170,
      "fixed": false,
      "notes": ""
    }
  ],
  "links": [
    {
      "id": "l1",
      "source": "me",
      "target": "org_chr",
      "label": "избегает",
      "tone": "negative",
      "directed": true,
      "notes": ""
    },
    {
      "id": "l2",
      "source": "me",
      "target": "medic",
      "label": "лечится",
      "tone": "neutral",
      "directed": true,
      "notes": ""
    }
  ]
}
```

`group`: `self`, `ally`, `friend`, `family`, `love`, `colleague`, `client`,
`acquaintance`, `enemy`, `org`, `other`. Категория `org` означает организацию
(первичный центр) — это полноценная нода, концом связи может быть что угодно.
`faction` — произвольная строка (до 80 символов) или пустое значение; именно она
определяет, в какой визуальный блиб попадает нода. У ноды-организации обычно
та же строка, что и в `label`. Значения «Без Фракции», «нет фракции», `none` и
подобные при загрузке превращаются в пустое: это не фракция, поэтому цвет, блиб
и притяжение для таких нод не создаются.
Поля `zones` и `zone` больше не используются: старые карты с массивом `zones`
при загрузке превращают эти записи в ноды-центры с теми же ID, поэтому связи
со старыми зонами сохраняются.

`tone`: `positive`, `neutral`, `negative`, `work`, `family`, `other`.

Координаты `x`/`y` и `fixed` необязательны — без них граф разложится сам.
`fixed: true` — персонаж закреплён и не двигается при раскладке.
Неизвестные категории и типы при импорте заменяются на `other`/`neutral`,
битые связи и дубли ID отбрасываются. Несколько связей между одной парой (`source`/`target`)
допустимы и при импорте не сливаются: это разные отношения.

## Разработка

- Без сборки и зависимостей: `index.html`, `style.css`, `app.js`, `graph.js`,
  `store.js`, `file.js`.
- Открывать через локальный HTTP-сервер (ES-модули и `fetch` не работают с `file://`).
- Тесты модели: `node tests/relationships.test.mjs`.
